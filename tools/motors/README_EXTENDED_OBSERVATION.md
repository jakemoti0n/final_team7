# 캐스터 정렬 전후의 유한 관찰 시간 비교

이 변경은 같은 저속 목표와 출력 상한으로 좀 더 긴 움직임을 관찰하기 위한 명시적 시간 경계다. 캐스터가 끊김의 원인이라는 결론이나 부드러운 주행의 검증 완료를 뜻하지 않는다.

기본 `extended_observation=false`와 최대 5초 제한은 유지한다. 실행 전에 `extended_observation=true`를 명시한 경우만 `duration_seconds`를 최대 10초로 선택할 수 있다. ROS 파라미터는 읽기 전용이며 transport에도 같은 bool을 전달한다. transport가 단일 arm에서 최대 시간을 다시 검사한다. bool 대신 문자열·숫자 등을 직접 넘기는 입력은 거부하고, launch는 `true`와 `false`만 받아 실제 bool로 바꾼다. 10초를 넘거나 동일 세션을 다시 arm하는 요청은 허용하지 않는다.

이번 비교의 목표는 전진 0.02m/s, 최대 10초다. 명시적 출력 상한 4915(약 15%), Kp 0.06, Ki 0.20, feedforward gain 0.3375, 정확 100ms 속도 창을 유지한다. 일반 실행의 기본 상한 3276과 기본 PI/추정 설정은 그대로다. 캐스터의 위치·개수 및 움직임 관찰 준비와 기존 빈 경로·차단 담당자 준비를 확인한 뒤 명령 전에 안내한다.

보고 전류 3A, 바퀴 속도 0.3rev/s와 양자화 여유 2카운트, 모터별 누적 절대 1500카운트, 피드백 최대 0.15초, 반대 방향·비활성 바퀴 검사, 목표 각속도·출력 변화율·정지 경계는 변경하지 않는다. 목표 속도를 계속 유지하면 10초 안에 1500카운트 경계에 이를 수 있다. 이 경우 기존 guard에 따라 먼저 종료하며, 관찰 시간을 채우려고 이동량을 늘리거나 자동으로 재시도하지 않는다.

명시적 zero, 시간 종료, 통신/guard 예외에서는 기존 정지 및 포트 종료 경로를 사용한다. 최대 관찰 시간은 호스트 프로그램의 한계이며 OS·USB·전원 장애에서의 물리적 정지를 보장하는 수치는 아니다. 기존 하드웨어 차단 준비와 보드 timeout 검사를 유지한다. 연속 주행, 일반 cmd_vel 중단 감지, Nav2 및 보드/NVM 설정 변경은 포함하지 않는다.

summary에는 `duration_envelope='finite_observation_10s_v1'`와 `settings.extended_observation=true`를 함께 기록한다. 기본은 `finite_trial_5s_v1`와 false다. `limits`에 실제 요청 시간, 허용 최대 시간, 선택 duty 상한 및 기존 guard 수치를 기록한다. duty envelope와 제어기·추정기 모델은 유지한다. 분석기는 시간 태그가 없는 이전 자료를 최대 5초로 처리하고, 알 수 없거나 bool과 일치하지 않는 태그를 거부해야 한다. 실행·정지 성공과 주행 성능 판정은 구분한다.

검사 범위는 기본 5초 거부 경계, 명시적 10초 허용/초과 거부, 잘못된 bool 거부, 재arm 거부, 1500카운트 guard와 정지 유지, ROS 시간 파라미터 불변성·전달·메타데이터 및 10초 종료다. 실제 관찰 결과는 별도 시험 기록에 추가한다.
