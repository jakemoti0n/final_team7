# 바퀴를 띄운 상태의 유한 시간 ROS 속도 제어

`wheel_speed_bench`는 ROS 목표 한 개를 받아 최대 5초 동안 엔코더 피드백으로 모터 속도를 조절한 뒤 정지하는 시험 노드입니다. Jetson의 PI 계산 결과를 RoboClaw duty 명령으로 보냅니다. 연속 `/cmd_vel` 주행 브리지나 Nav2 실행 노드가 아닙니다.

사용자가 보류한 일반적인 명령 중단 watchdog·상위 안전 통합은 이 도구에 포함하지 않습니다. 대신 시험마다 목표·시간·출력·이동량을 제한하고, 0 명령·오류·종료 시 실제 정지를 확인합니다. RoboClaw 내부 PID/QPPS·엔코더 모드·NVM 설정을 바꾸지 않습니다.

## 실행 조건

- 차체를 튼튼한 받침에 고정해 양쪽 바퀴가 바닥에서 완전히 떨어지고 주변이 비어 있어야 합니다. 손으로 차체를 들고 출력 시험하지 않습니다.
- 이전에 확인한 +극 부하 차단 장치 옆에 하드웨어 담당자가 대기합니다. USB 분리나 −극 분리를 이 차단 수단 대신 사용하지 않습니다.
- RoboClaw 주전원·USB를 연결하고 Motion Studio와 다른 제어 프로그램을 해제합니다. **기존 `roboclaw_encoder`·`run_readonly.sh`·`run_odometry.sh`를 동시에 실행하지 않습니다.** 이 노드가 직렬 포트의 단일 소유자가 되어 count·JointState를 직접 발행합니다.
- 시작 점검은 정확한 장치·펌웨어, 통신 timeout raw5(0.5초), 배터리·상태, PWM0·카운트 정지를 확인합니다. 값이 맞지 않으면 시작하지 않으며 자동으로 설정을 고치지 않습니다.

wrapper의 기본값은 `ROS_DOMAIN_ID=97`, `ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST`입니다. 다르게 지정할 경우 관측·명령 터미널도 같은 값을 사용해야 합니다. 모든 예시는 Jetson에서 실행합니다.

## 오른쪽 전진 0.02m/s 예시

세 터미널을 미리 준비합니다. 관측·발행 터미널에는 다음 환경을 먼저 적용합니다.

```bash
source /opt/ros/jazzy/setup.bash
source ~/limbo/limbo/install/local_setup.bash
export ROS_DOMAIN_ID=97
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
```

**관측 터미널:** 상태를 먼저 구독합니다. `ready`는 시작 명령 대기 상태이며, 아직 모터 출력은 없습니다.

```bash
ros2 topic echo /limbo/drive_bench/status
```

**실행 터미널:** 아직 존재하지 않는 기록 폴더와 정확한 좌우 목표를 지정합니다. `enable_output`의 기본값은 false이므로 true를 명시해야 합니다. 이 명령만으로 회전이 시작되지는 않습니다.

```bash
_speed_record_dir="$HOME/limbo_speed_bench_records/right_forward_$(date +%Y%m%d_%H%M%S)"
bash ~/limbo/tools/motors/run_speed_bench.sh \
  enable_output:=true \
  record_dir:="$_speed_record_dir" \
  left_target_rad_s:=0.0 \
  right_target_rad_s:=0.2666666667 \
  duration_seconds:=5.0
```

**명령 터미널:** 차단 담당자에게 시작을 알리고 `ready`를 확인한 뒤, 아래 목표를 **한 번만** 발행합니다. 오른쪽만 전진하려면 차체 Twist가 `v=0.01m/s`, `ω=+0.037037…rad/s`여야 합니다. 명령을 받으면 정지 사전 점검 후 최대 5초 제어를 시작합니다.

```bash
ros2 topic pub --once /limbo/drive_bench/cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.01}, angular: {z: 0.03703703703703704}}'
```

시작 후 더 빨리 종료하려면 0 명령을 한 번 보냅니다.

```bash
ros2 topic pub --once /limbo/drive_bench/cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.0}, angular: {z: 0.0}}'
```

`-r`로 반복 발행하지 않습니다. 두 번째 nonzero 명령은 기존 시험을 연장하지 않고 오류로 종료합니다. 설정한 목표와 다른 nonzero 명령도 거절·종료합니다. 종료한 노드는 새 명령으로 재시작되지 않으므로 다음 시험은 새 기록 폴더·새 실행으로 시작합니다. 준비 상태에서 30초 동안 명령이 없으면 해당 실행을 종료합니다.

## 다른 방향의 목표값

아래 표는 양쪽 반지름 0.075m·중심 간격 0.54m에서 바퀴 선속도 절댓값 0.02m/s에 해당합니다. 각 행은 별개의 시험이며 자동으로 순서대로 구동하는 설정이 아닙니다. 개별 좌우 검증을 끝낸 뒤 양쪽 동시 시험을 진행합니다.

| 시험 | left_target_rad_s | right_target_rad_s | Twist linear.x (m/s) | Twist angular.z (rad/s) |
|---|---:|---:|---:|---:|
| 오른쪽 전진 | 0 | +0.2666666667 | +0.01 | +0.03703703703703704 |
| 오른쪽 후진 | 0 | −0.2666666667 | −0.01 | −0.03703703703703704 |
| 왼쪽 전진 | +0.2666666667 | 0 | +0.01 | −0.03703703703703704 |
| 왼쪽 후진 | −0.2666666667 | 0 | −0.01 | +0.03703703703703704 |
| 양쪽 전진 | +0.2666666667 | +0.2666666667 | +0.02 | 0 |
| 양쪽 후진 | −0.2666666667 | −0.2666666667 | −0.02 | 0 |

표의 음수 기호를 명령에 입력할 때는 일반 ASCII `-`를 사용합니다. 물리 치수·CPR을 변경한 경우 위 Twist를 그대로 재사용하지 않고 공유 설정으로 다시 계산해야 합니다.

## 제어·제한값

기하 값은 기존 `wheel_odometry.yaml`, CPR은 `encoders_readonly.yaml`에서 읽습니다. 현재 양쪽 반지름 0.075m, 중심 간격 0.54m, CPR은 왼쪽 3688·오른쪽 3607의 임시값입니다. 속도 변환은 `ω_L=(v−ωb/2)/r_L`, `ω_R=(v+ωb/2)/r_R`입니다.

M1=오른쪽, M2=왼쪽입니다. 양수 duty는 두 모터 모두 전진이며, 원시 엔코더 전진 부호는 M1+, M2−입니다. 피드백 부호를 정규화한 뒤 PI를 계산하고, 모터 출력에는 M2 부호를 다시 뒤집지 않습니다.

| 항목 | 현재 시험 설정 |
|---|---|
| 최대 시간 | 5초; 새 ROS 명령으로 연장하지 않음 |
| 바퀴 목표 상한 | 각 바퀴 절댓값 0.4rad/s |
| P / I / D | 0.10 / 0.20 / 0; duty fraction·rad/s 단위의 호스트 PI |
| 목표 변화율 | 0.4rad/s²; 정지 요청은 즉시 zero |
| 출력 변화율 | duty fraction 0.15/s; 정지 요청은 제한 없이 zero |
| 출력 절댓값 | raw3276 이하, 약10% duty; 물리 속도10%라는 뜻은 아님 |
| 제어 표본 간격 | 0.02~0.15초, 목표 실행 주기 약20Hz |
| 전류 보고값 중단 한계 | 각 채널 절댓값3A; 모터 정격이나 외부 계측 peak 값이 아님 |
| 속도 중단 한계 | 각 채널0.3회전/초와 표본당2카운트의 양자화 여유 |
| 누적 이동 중단 한계 | 각 채널 카운트 절댓값 누적1500 |

PI는 포화·출력 변화율 제한을 고려해 적분 누적을 억제합니다. zero에서는 적분 상태를 즉시 지우며, 목표와 반대 방향 duty로 적극 제동하지 않습니다. 통신·상태·방향·표본 시간 오류는 nonzero 출력을 중단합니다. 종료 시 양쪽 zero ACK, PWM0, 연속 정지 카운트를 확인합니다. zero ACK를 얻지 못하면 읽기 polling까지 멈추며 물리 차단 확인이 필요합니다.

## ROS 출력과 기록

| 토픽 | 내용 |
|---|---|
| `/wheel/encoder_counts` | 기존 `WheelEncoderCounts` 계약; 원시 M1/M2와 정규화한 좌우 delta·total |
| `/wheel/joint_states` | 실제 각도·각속도; 순서는 오른쪽·왼쪽이며 이름으로 대응 |
| `/limbo/drive_bench/target_joint_states` | 실제 제어에 사용한 램프 적용 목표 각속도; 왼쪽·오른쪽 순서 |
| `/limbo/drive_bench/status` | 상태, 고정 목표, 최신 측정값, 제어 단계 수·상한 |

각 기록 폴더에는 `wire.jsonl`, `samples.jsonl`, `control.jsonl`, `events.jsonl`, `summary.json`이 남습니다. 원시 카운트·필터 속도·목표·duty·전류·상태·종료 결과를 함께 확인합니다. `summary.json`의 기본 `passed`는 유한 실행과 정지 절차 결과이며, 별도 분석의 속도 추종 판정과 구분해야 합니다.

실험의 추종 기준은 ramp 이후 마지막 1.5초 raw count 기반 평균 오차가 `max(목표 절댓값의10%, 0.015rad/s)` 이내이고, 같은 구간 필터 속도 오차의 p95가 `max(목표 절댓값의20%, 0.03rad/s)` 이내인지 확인하는 것입니다. 방향·출력 포화·정지·통신 검사도 따로 확인합니다. 이 기준은 공중 저속 시험의 기능 판정이며, 바닥 주행 성능·부하 응답이나 인증 기준이 아닙니다.

20Hz 단일 표본의 한 카운트는 약0.034rad/s입니다. 따라서 목표0.2667rad/s에서 모든 순간 측정값이 목표와 정확히 같아야 한다고 판단하지 않습니다. 최종 평균은 raw count와 실제 시간으로 계산하며 필터만으로 이상값을 숨기지 않습니다.

## 확인된 범위

2026-10-30 개별 바퀴 시험에서 목표±0.2667rad/s에 대해 오른쪽 전진 평균 +0.2822rad/s(오차 +5.83%)·후진 −0.2726rad/s(속도 크기 오차 2.23%), 왼쪽 전진 +0.2702rad/s(오차 +1.33%)·후진 −0.2619rad/s(속도 크기 오차 1.77%)와 종료 정지를 확인했습니다. 최초 바닥 접촉 상태의 오른쪽 실패, 접촉 가능성이 있던 왼쪽 실패, 재고정 뒤에도 반복된 왼쪽 정체 기록을 모두 보존했습니다. 전원 OFF 상태의 손회전 확인·전원 재기동·시작 위치 변경 후 같은 계수와 출력 상한에서 왼쪽 전후진이 통과했으나, 앞선 왼쪽 정체 원인은 확정하지 않았습니다. 양쪽 동시 구동은 사용자 자리 비움에 따라 보류했습니다. 최종 결과는 누적 점검 보고서와 원자료를 기준으로 확인합니다.

실제 전원 재기동 뒤 보드 timeout이 raw0으로 돌아간 것을 관측했고, 무출력 상태에서 기존 raw5(0.5초)만 다시 설정했습니다. 이 노드는 값을 자동 복구하지 않고 raw5가 아니면 시험을 거절합니다. NVM 저장은 하지 않았으므로 전원 재기동 후 다시 읽어 확인해야 합니다. 본 시험의 원시 카운트는 서로 다른 전원·노드 세션 사이에서 이어 붙이지 않습니다.

이 도구에는 연속 주행, Nav2 명령 중재, 배선·기하 보정, RoboClaw 내부 PID/QPPS 튜닝, NVM 저장 기능이 없습니다. 다음 단계에서는 실제 부하에서 속도·정지 동작과 별도로 보류한 명령 중단 정책을 통합·검증해야 합니다.
