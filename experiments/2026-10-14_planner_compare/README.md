# 전역 경로 계획기 비교: NavFn(지금) vs Smac 2D vs Theta* (2026-10-14, 메인 PC)

## 왜 했나
PROJECT 다음 5번. 사람 있는 조건(소셜 포스 사람, 새 지표)에서 전역 계획기가 시간·경로 길이·복구·사람 거리·전역 경로 변경·벽 거리에 차이를 내는지 선별. 충장로는 최종 단계 장소라 선별에서 뺌(사용자 결정).

## 조건
- 커밋 `1af5141`(전역 STVL 3초, HumanLayer 치명, `prune_distance` 2.5, 카메라 0.7 m 15°). **Nav2 기본 BT**(lab에 켜 둔 기다리기 BT는 비켜 주는 사람 복도에서 60번 기다리다 포기해 끔)
- 계획기 설정(`run.sh`가 `GridBased` 블록만 바꿈, 나머지 동일):
  - NavFn: `use_astar true, tolerance 0.5, allow_unknown true` (지금)
  - Smac 2D: `tolerance 0.5, cost_travel_multiplier 2.0, max_planning_time 2.0, smoother(w_smooth 0.3, w_data 0.2)`
  - Theta*: `how_many_corners 8, w_euc_cost 1.0, w_traversal_cost 2.0`
- 경로: 비켜 주는 사람 복도(`aischool_2f_social` `people2`, 2·3행이 복도 구간), 홀 손님(`zz_social_approach` `hall` 4구간). 조건당 1회
- 벽 거리는 `nav_recorder`가 `/map` 거리 변환으로 잰 정답 위치 기준(이번에 추가한 열). 계획 계산 시간은 Nav2가 로그로 내지 않아 못 쟀음

## 결론
- **복도에서는 셋이 같다.** 경로 길이 20.3~20.4 m, 시간 51~56 s, 사람 거리 0.81~0.83 m, 충돌 0. 좁은 복도라 경로가 하나뿐이어서 계획기 차이가 드러날 자리가 없다
- Smac 2D는 전역 경로 변경이 13번(NavFn 4)으로 많고 MPPI "모든 후보 충돌" 경고도 11번(NavFn 2). 평활기가 매번 다른 경로를 내는 것으로 보임. 1회라 단정은 못 하지만 이 조건에선 이점이 없다
- Theta*는 복도에서 벽 최소 거리가 0.55 m로 가장 멀지만(NavFn 0.45, 직선 경로의 성질) 홀 재실행에서 한 구간에 복구 6번·65.7 s(NavFn 53.5 s, 복구 0)로 손님 옆에서 머뭇거림. 1회라 단정은 못 하지만 이점이 없다
- **NavFn 유지.** 바꿀 근거가 없다. 계획기 차이는 넓고 열린 공간(충장로 번화가)에서 다시 봐야 하며, 그때 계획 계산 시간(`/plan` 지연)도 재야 한다

- 계산 시간은 다익스트라가 2~3배지만 둘 다 6 ms 안이라 문제가 안 된다(1초 재계획 주기 대비 1 % 미만)
- 경로는 다익스트라가 두 목표에서 0.3~1.3 m 짧다. NavFn의 A*는 비용 가중이 들어간 휴리스틱이라 최단을 보장하지 않는 알려진 성질. 대신 다익스트라 경로는 구석에 더 붙어 복도·홀 주행에서 MPPI "모든 후보 충돌" 경고가 10번(A* 0번) 났다
- **주행 벤치(복도·홀 각 1회)는 계획기 비교에 못 썼다.** 둘 다 복도 둘째 구간에서 기다리기 트리의 "다가옴 정지"가 60 s 상한까지 가서(A* 86.4 s, 다익스트라 78.2 s ABORTED) 시간·복구가 계획기와 무관하게 결정됨. 이 정지 재발은 서브 PC R5 몫으로 넘김(`trial_pl_*_corridor.csv`, `sim_pl_*_corridor.log`)
- 결론: **A* 유지.** 계산 시간 이점(작지만 공짜)에 구석을 덜 깎는 경로. 다익스트라의 짧은 경로가 주행에서 이득인지는 기다리기 트리 문제가 정리된 뒤 다시 봐야 한다
