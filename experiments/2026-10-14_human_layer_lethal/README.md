## 결론
- **복도 통과와 상자 회피는 유지된다.** 시간 차이 ±2 s, 충돌 0, 상자 닿음 0
- 치명 비용이 들어가니 사람 옆을 비집고 지나가는 대신 **멈추고**(사람 앞 멈춤 2.3 → 3.3 s), 10 s 진전 없음 → costmap 비우기 복구로 넘어간 뒤 지나갔다. 이 "진전 없음 → 복구"가 R4(BT 기다리기)에서 Wait로 바뀔 자리다
- 복도→동 구간의 사람 최소 0.34 m는 전(0.53)보다 가깝다. 멈춘 로봇 쪽으로 actor가 걸어온 것인지(actor는 비켜 주지 않음), 카메라 시야 밖(옆)에서 예측이 끊겨 치명이 사라진 것인지 bag이 없어 확정 못 함. 0.3 m 기준으로는 충돌 아님
- HumanLayer는 카메라가 본 사람만 안다(가로 72°). 옆으로 스치는 순간은 LiDAR(STVL)가 맡는다

- 1회차 실패는 사람이 아니라 **controller_server가 4초 넘게 응답을 못 해 lifecycle manager가 Nav2 전체를 내린 것** (`CRITICAL FAILURE: SERVER controller_server IS DOWN after not receiving a heartbeat for 4000 ms`, 사람 두 명이 새로 잡힌 직후). 2회차엔 없음. 알려진 문제 heartbeat 계열, 주행 중에 난 첫 사례

- 치명 비용 때문에 로봇이 사람 앞에서 더 오래 멈춘다(2회차 A→C 멈춤 24.7 s 중 사람 앞 17.5 s). 쓰레기통 용도(2-1)로는 맞는 행동이지만, 지금 시뮬레이션 사람으로는 "멈췄더니 뚫고 지나감"이 돼 성적으로는 안 보인다
- MPPI `Optimizer fail` 15·23번 (전: 네모 화면에서 안 셈)

## 결론 (전체)
- HumanLayer 치명 비용은 복도·상자 성적을 유지하면서 로봇이 사람 몸으로 들어가는 궤적을 막는다. 채택
- **사람 10명 방에서는 지표가 로봇 탓과 사람 탓을 못 가른다.** 다음 두 가지가 먼저: (1) 비켜 주는 소셜 포스 사람(PROJECT 다음 4번) — 이게 없으면 사람 있는 평가는 전부 이 한계를 안고 있음. (2) nav_recorder에 "최소 거리 순간의 사람 접근 속도" 열(사람이 걸어 들어온 충돌 구분)과 NavigateThroughPoses 지원
