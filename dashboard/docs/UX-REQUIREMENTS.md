# 관제 화면 UX 요구사항 (초안)

- 작성일: 2026-11-13
- 대상: `dashboard/ui` 실제 화면(`/`)과 데모 화면(`/demo`)
- 문서 상태: **초안**. 현재 화면이 이미 지키는 규칙(유지)과 리팩터링에서 새로 채울 요구(신규)를 함께 적었다. 각 항목 끝의 **[유지]**·**[신규]** 표시로 구분한다.
- 관련: [UI-REFACTORING-PLAN.md](UI-REFACTORING-PLAN.md), [COMPONENT-INVENTORY.md](COMPONENT-INVENTORY.md), [PRD.md](PRD.md), [../../docs/CONTROL_SCREEN.md](../../docs/CONTROL_SCREEN.md)

## 1. 사용자와 사용 환경

| 항목 | 내용 |
|---|---|
| 사용자 | 로봇 운영자(팀원). 계정은 모두 관리자 한 등급 — 관제 조작과 회원 관리 모두 가능 |
| 장치 | 노트북·데스크톱 브라우저(주), iPhone Safari(현장 확인용) |
| 상황 | 로봇이 순찰하는 동안 화면을 켜 두고 가끔 본다. 문제가 생기면 멈추거나 재개한다 |
| 네트워크 | 학교·현장 Wi-Fi, 휴대폰 LTE. 끊김·지연이 흔하다 |
| 운영자가 답을 얻어야 하는 질문 | ① 지금 로봇 상태를 믿을 수 있나? ② 로봇은 어디서 무엇을 하나? ③ 내 명령이 실제로 실행됐나? ④ 확인해야 할 문제가 있나? |

## 2. 핵심 원칙

1. **모르는 것은 모른다고 표시한다.** 데이터가 오지 않으면 마지막 값을 "지금 값"처럼 보이지 않는다. 마지막 값은 흐리게 + "마지막 수신 값" 표시 + 받은 시각. **[유지]**
2. **성공은 확인된 뒤에만.** 명령은 서버가 `confirmed`(로봇이 보낸 이후 상태로 확인)일 때만 성공(초록)이다. 클릭·전송·202 응답은 "진행 중". **[유지]**
3. **자동 재전송하지 않는다.** 결과를 모르면 "확인 불가"로 끝내고 운영자가 판단한다. **[유지]**
4. **추정하지 않는다.** 속도 0을 "일시정지됨"으로 보지 않는다. 재개 가능 여부는 순찰 노드의 `has_resumable_task`로만 판단한다. **[유지]**
5. **문제의 위치를 알려 준다.** "안 된다" 대신 어느 구간(내 브라우저·서버·로봇·센서)이 문제인지 말한다. **[신규 — 브라우저↔서버 구간 세분화]**
6. **버튼이 잠긴 이유를 항상 보인다.** 비활성 버튼 옆이나 아래에 사유 문구를 둔다. 마우스 오버(`title`)에만 의존하지 않는다(휴대폰에서 안 보임). **[일부 유지 · 신규]**
7. **색만으로 구분하지 않는다.** 톤마다 기호·아이콘 모양·문구가 다르다. **[유지]**

## 3. 연결·데이터 상태 모델 — 끊김과 지연의 구분

### 3.1 세 구간

```text
[브라우저] ──① 링크── [관제 서버] ──② Bridge── [로봇] ──③ 토픽── [센서·노드]
```

| 구간 | 판단 주체 | 상태 값 |
|---|---|---|
| ① 브라우저↔서버 | 화면(`LiveProvider`) | `connecting` · `live` · `stale` · `reconnecting` · `offline` |
| ② 서버↔로봇 | 서버 → 스냅샷 `bridge.status` | `checking` · `connected` · `delayed`(≥ `bridge_delay_s`, 기본 3초) · `disconnected`(≥ `bridge_disconnect_s`, 기본 10초) |
| ③ 데이터(토픽) | 서버 → 스냅샷 `topics[*].status` | `receiving` · `delayed`(≥ `topic_delay_s`) · `never_received` · `unknown` |

①의 다섯 값 정의 **[신규]**:

| 값 | 조건 | 의미 |
|---|---|---|
| `connecting` | 처음 열었거나 로봇을 바꿔 첫 스냅샷을 기다림 | 아직 정보 없음 |
| `live` | 최근 `browser_delay_s`(기본 3초) 안에 스냅샷을 받음 | 정상 |
| `stale` | 소켓은 열려 있으나 `browser_delay_s` 넘게 새 스냅샷 없음 | **지연** — 서버가 느리거나 네트워크가 막힘 |
| `reconnecting` | 소켓이 닫힘, 백오프(1·2·4·8·10초) 대기 중 | **끊김** — 다시 연결 시도 중 |
| `offline` | 브라우저가 오프라인(`navigator.onLine === false`) | 내 장치의 네트워크 문제 |

> 현재 구현은 `stale`이 감지되면 소켓을 닫고 재연결하므로 `stale`은 짧게(최대 감시 주기 200 ms) 보였다가 `reconnecting`으로 넘어간다. 판단 규칙은 바꾸지 않고, **화면은 "지연으로 다시 연결 중"과 "연결이 끊겨 다시 연결 중"을 구분해 표시**한다(마지막 끊김 원인을 기록).

### 3.2 상위 구간이 우선

- ①이 `live`가 아니면 ②·③은 **판단할 수 없음**이다. ②를 "연결 끊김"으로 그리지 않고 "확인 불가"(neutral)로 그린다. **[유지 — 현재 `serverProblem`이면 `unknown`]**
- ②가 `delayed`·`disconnected`면 ③은 서버가 `unknown`으로 보낸다. 화면은 그대로 "확인 불가". **[유지]**
- 헤더 요약은 **가장 위쪽의 문제 하나**를 대표로 보여 주고, 아래 구간은 펼쳐서 본다. **[신규]**

### 3.3 표시 규칙

| 상황 | 헤더 요약 | 경고 띠 | 카드 값 | 제어 버튼 |
|---|---|---|---|---|
| 모두 정상 | 정상 (good) | 없음 | 현재 값 | 규칙대로 |
| ① `connecting` | 확인 중 (neutral) | "서버에 연결하고 있습니다" (status) | "—" / 수신 대기 | 잠김 "연결을 확인한 후 사용할 수 있습니다" |
| ① `stale` | **수신 지연** (warn, 시계 아이콘) | "서버에서 새 정보가 늦게 오고 있습니다. 마지막 수신 N초 전" | 마지막 값 흐림 | 잠김 |
| ① `reconnecting` | **서버 연결 끊김** (bad, 끊김 아이콘) | "서버 연결이 끊겼습니다. N초 뒤 다시 연결합니다 (시도 k회) [지금 다시 연결]" | 마지막 값 흐림 + "확인 불가" | 잠김 |
| ① `offline` | **내 네트워크 끊김** (bad) | "이 기기가 인터넷에 연결되어 있지 않습니다" | 마지막 값 흐림 | 잠김 |
| ② `checking` | 확인 필요 (warn) | "로봇 연결을 확인하고 있습니다. 아직 받은 정보가 없습니다." | 수신 대기 | 잠김 |
| ② `delayed` | 확인 필요 · 로봇 수신 지연 (warn) | "로봇 상태가 늦게 오고 있습니다. 지금 상태는 확인할 수 없습니다." | 마지막 값 흐림 | 잠김 |
| ② `disconnected` | 연결 끊김 · 로봇 (bad) | "로봇과 연결이 끊겼습니다. 아래 정보는 마지막으로 받은 상태입니다." | 마지막 값 흐림 + "(마지막 상태)" | 잠김 |
| ③ 일부 지연·미수신 | 확인 필요 · 해당 항목 이름 (warn) | 없음 | 해당 항목만 경고 | 규칙대로 |

- 경고 띠의 ARIA: 확인 중은 `role="status"`, 지연·끊김은 `role="alert"`. **[유지]** 같은 상태가 계속되는 동안 매초 다시 읽히지 않게 문구의 숫자 부분은 live region 밖에 둔다. **[신규]**
- "N초 전"은 서버가 준 `age_s` + 받은 뒤 지난 시간으로 계속 늘어난다. 1초 미만은 소수 한 자리. **[유지]**
- 표시 시각은 Asia/Seoul. 오늘이 아니면 날짜를 붙인다. **[유지]**

### 3.4 로그인·서버 도달 불가

- 로그인 확인 단계에서 서버에 닿지 않으면 "관제 서버에 연결할 수 없습니다. 5초마다 다시 시도합니다" + [지금 다시 시도]. **[유지]**
- 로그인이 끝나면(로그아웃·만료·계정 변경, WebSocket 4401 포함) 로그인 화면으로 돌아가며 이유를 알린다. **[유지]**
- 선택한 로봇을 서버가 모르면(WebSocket 4404) 재연결을 반복하지 말고 "서버가 이 로봇을 모릅니다" + 로봇 목록 열기. **[신규]**

## 4. 영역별 요구사항

### 4.1 헤더

- 제품명, 현재 로봇(누르면 목록), 연결 요약(3장), 계정 메뉴. **[유지]**
- 로봇 목록 항목마다 연결 상태 배지. 진행 중인 요청이 있으면 "진행 중인 요청은 {로봇}에서 계속 처리됩니다". **[유지]**
- 로봇 선택은 URL(`?robot=`)과 이 브라우저에 기억. 서버가 모르는 로봇이면 기본 로봇으로. **[유지]**
- 휴대폰(≤ 699 px): 한 줄에 로봇·요약 배지만, 세부 연결 정보와 계정 메뉴는 접기. **[신규]**
- 데모 화면은 페이지 맨 위에 "데모 데이터 · 실제 로봇을 제어하지 않습니다" 띠를 항상 보인다. **[유지]**

### 4.2 로봇 상태 (순찰·이동)

- 순찰 상태 문구: 위치 확인 중 / 순찰 중 / 순찰 중 · 이동 다시 시도 (n/m) / 멈추는 중 / 일시정지 / 이동 실패 · 확인 후 재개 / 순찰 완료 / 순찰 실패 / 순찰 상태 확인 불가. **[유지]**
- 다음 목표: "다음 목표 {이름} (i/N)", 완료 시 "N개 지점 모두 지남". **[유지]**
- 이동: 이동 중 / 정지 상태 / 확인 불가, 선속도(m/s 소수 둘째 자리), 회전 중. 값이 마지막 값이면 흐림 + 배지. "멈춰 있다고 일시정지가 확인된 것은 아닙니다" 안내 유지. **[유지]**
- 휴대폰에서 순찰·이동 카드가 제어 버튼 바로 아래에 와야 한다(현재: 제어 → 요약 → 지도 순). **[유지]**

### 4.3 지도

- 지도 그림 위에 경로·waypoint·내 로봇(방향 + 2σ 오차 원)·같은 지도의 다른 로봇. **[유지]**
- 위치가 오래되면(`pose.stale`) 로봇 표시를 흐리게 하고 "위치 확인 불가 · 마지막 위치 N초 전". **[유지]**
- 로봇 따라가기 ↔ 전체 지도. 확대해도 표시·글자 크기 일정. **[유지]**
- 다른 로봇을 누르면 그 로봇 화면으로 전환(키보드 가능). waypoint 편집 중에는 전환 금지. **[유지]**
- 지도를 받지 못하면 "서버에 지도가 설정되지 않았습니다" / "지도를 불러오는 중입니다". **[유지]**
- 범례는 지도 아래에 항상 표시. **[유지]**
- (검토) 휠·핀치 확대와 끌어 이동, 다음 목표까지 거리 표시. **[신규 · 선택]**

### 4.4 로봇 제어

- 주 버튼 하나가 상황에 맞게 바뀐다: 주행 시작 / 주행 정지 / 주행 재개. 정지는 빨강 큰 버튼, 재개·시작은 청록 테두리. 순찰 종료는 별도 보조 버튼. **[유지]**
- 버튼 위에 지금 누르면 무엇을 하는지, 잠겼으면 왜 잠겼는지 문구. **[유지]**
- 진행 표시 3단계: 요청 전송 → 로봇 응답 → 상태 확인. 각 단계 대기·진행 중·완료·실패·확인 불가. 요청 시각·경과·요청 ID. 60초 지나면 한 줄로 접힘(자세히 버튼). **[유지]**
- 진행 중에는 같은 버튼을 다시 누를 수 없고 "정지 요청 중" 등으로 바뀐다. **[유지]**
- 순찰 노드가 0이 아닌 코드로 끝났으면 종료 코드·로그 위치를 보인다. **[유지]**
- 정지 버튼은 화면 어디서든 찾기 쉬워야 한다: 휴대폰에서 스크롤해도 하단 고정(sticky) 정지 버튼 검토. **[신규 · 검토]**
- 위험 동작(순찰 종료)은 한 번 더 확인을 받을지 결정 필요(현재는 바로 실행). **[열린 결정]**

### 4.5 Waypoint

- 목록: 이름, 종류(정지·통과), 좌표(m 소수 둘째 자리), 개수. **[유지]**
- 동작: 새 지점(이름·종류 + 지도 클릭), 위치 교체(지도 클릭), 이름 변경(Enter 저장·Esc 취소), 삭제, 순서 변경. **[유지]**
- 규칙: 이름 1~32자·중복 금지(대소문자 무시), 마지막 지점은 정지 지점, 마지막 정지 지점 삭제 불가. 위반 시 이유 문구. **[유지]**
- 순찰 노드가 실행 중이거나 시작·종료 명령 처리 중이면 편집 잠금 + "주행 완료 후 변경 가능합니다". **[유지]**
- 저장 후 "저장했습니다. 순찰 노드를 다시 시작하면 적용됩니다". 다른 곳에서 바뀌었으면(409) 목록을 새로 받고 안내. **[유지]**
- **순서 변경을 키보드·터치로도 할 수 있어야 한다** (↑/↓ 버튼 또는 "위로/아래로 이동" 메뉴). **[신규]**
- 지도와 목록이 서로 강조: 목록 항목에 마우스·포커스 → 지도 지점 강조, 지도 지점 클릭 → 목록 항목으로 스크롤(편집 모드 아닐 때). **[신규 · 검토]**
- 저장되지 않은 편집 중에 로봇을 바꾸거나 페이지를 떠나면 경고. **[신규]**

### 4.6 이벤트 로그 (최근 알림)

- 시각 · 심각도(정보·주의·오류) · 문구 · 지속 중 표시, 최신순. 없으면 "최근 알림이 없습니다". **[유지]**
- 심각도 필터, "지속 중인 문제만", 전체 건수(서버 보관 최대 100건임을 표시). **[신규]**
- 처음 10건만 펼치고 "더 보기". **[신규]**
- 지속 중인 문제(`active`)는 목록 맨 위 요약으로도 보인다. **[신규 · 검토]**

### 4.7 센서 수신 상태

- 토픽 4종(주행 정보·LiDAR 원본·LiDAR 필터 결과·카메라 원본) × 수신 상태·마지막 수신·Hz. 기본 접힘, "개발자용". **[유지]**
- "수신 상태는 데이터가 들어오는지만 나타냅니다. 센서 정상 작동 판단 정보가 아닙니다" 문구 유지. **[유지]**
- 접힌 상태에서도 제목 옆에 요약("4개 중 3개 수신 중")을 보인다. **[신규]**

### 4.8 로그인·계정

- 로그인, 첫 로그인 비밀번호 강제 변경, 비밀번호 변경(다른 세션 끊김 안내), 회원 관리(추가·임시 비밀번호 초기화·사용 중지·삭제, 자기 자신은 제외). **[유지]**
- 로그인 화면에서 데모 화면으로 가는 링크. **[유지]**
- 오버레이는 열릴 때 첫 입력으로 포커스, 안에서만 Tab 순환, 닫으면 연 버튼으로 포커스 복귀, Esc로 닫기. **[신규 — 현재는 Esc만]**

## 6. 접근성

- 모든 기능을 키보드만으로 사용 가능 (waypoint 순서 변경 포함). **[신규 부분 있음]**
- 포커스 링: 3 px 청록 윤곽, 2 px 이상 대비. **[유지]**
- 상태 변화는 `role="status"`·`alert`로 알린다. 버튼 이름은 동작을 그대로 말한다("주행 정지"). 아이콘은 `aria-hidden`. **[유지]**
- 글자·배경 대비 WCAG AA(본문 4.5:1, 큰 글자 3:1). 흐린 "마지막 값"도 AA 유지. **[신규 — 현재 `opacity: .35`인 지도 표시 점검]**
- `prefers-reduced-motion`이면 움직임 없음. **[유지]**

## 9. 인수 기준 (리팩터링 완료 판단)

1. 3.3 표의 모든 행을 Mock 시나리오로 재현하고, 각 행의 헤더·띠·카드·버튼 표시가 표와 같다.
2. 브라우저↔서버 "지연"과 "끊김"이 아이콘·문구·색 중 둘 이상으로 구별된다.
3. 실제 서버에서: 서버 중지 → 재연결 중 표시와 시도 횟수, 서버 재시작 → 자동 복구. Bridge 중지 → 3초 뒤 로봇 수신 지연, 10초 뒤 로봇 연결 끊김.
4. 성공 표시가 `confirmed` 이전에 나오는 경로가 없다 (단위 테스트 유지).
5. 키보드만으로 로그인 → 로봇 전환 → 정지 → 재개 → waypoint 추가·순서 변경 → 로그아웃 가능.
6. 390 px 폭에서 가로 스크롤 없음, 정지 버튼이 첫 화면 안에 보임.
7. 기존 E2E·단위 테스트 전부 통과.
