1. Planner Server (Global Planner)

← 메인 목록

Planner Server는 Nav2 아키텍처에서 글로벌 경로 계획(Global Path Planning)을 전담하는 핵심 서비스입니다. 로봇의 현재 위치(Start)부터 사용자가 지정한 목표 위치(Goal)까지, Global Costmap 데이터를 기반으로 동적 장애물을 피하는 최적의 전체 경로를 계산합니다.

▲ [Planner Server] 지도 전체 관점에서 출발지(Start)부터 목적지(Goal)까지의 최적 경로 탐색
주요 역할 및 특징
  • Action Interface: nav2_msgs/action/ComputePathToPose 액션 인터페이스를 제공하여 경로 계산 요청 처리
  • Global Path 생성: 지도 전역 관점에서 장애물과의 충돌 위험도를 고려한 점(Pose)들의 배열(Path) 생성
  • 플러그인 구조: 알고리즘 변경 시 코드 재작성 없이 YAML 파라미터 변경만으로 플러그인 교체 가능
대표적인 Planner 플러그인
플러그인 명 알고리즘 특징 및 추천 로봇 타입
NavFn Planner Dijkstra / A* 가장 흔하게 사용되는 표준 Grid 기반 플래너 (차동 구동 로봇 추천)
Smac Planner 2D 2D A* (Cost-aware) NavFn 대비 고성능/고속 경로 탐색 지원
Smac Planner Hybrid-A* Hybrid A* 회전 반경이 존재하는 아커만 조향(Ackermann) / 자동차형 로봇 전용
Theta* Planner Theta* 그리드 선에 얽매이지 않고 대각선/자유각 경로를 매끄럽게 탐색
설정 및 코드 예시
📄 nav2_params.yaml (Planner Server & NavFn 설정 예시)
planner_server:
 ros__parameters:
   expected_planner_frequency: 20.0       # 경로 계산 주기 (Hz 단위, 초당 20회 재계산 요구)
   use_sim_time: true                     # 시뮬레이션 시간 사용 여부 (Gazebo 등 시뮬레이터 사용 시 true)
   planner_plugins: ["GridBased"]         # 사용할 글로벌 플래너 플러그인의 별칭(Alias) 목록
   
   # --- NavFn Planner 상세 파라미터 설정 ---
   GridBased:
     plugin: "nav2_navfn_planner/NavfnPlanner" # NavFn 플래너 C++ 클래스 지정
     tolerance: 0.5            # 목표점(Goal) 주변 탐색 허용 오차 범위 (m 단위)
     use_aster: true           # true: A* 알고리즘 사용, false: Dijkstra 알고리즘 사용
     allow_unknown: true       # 미탐색(Unknown) 영역을 통과 경로에 포함할지 여부
💻 Python rclpy Action Client (ComputePathToPose 호출 예시)
import rclpy                                      # ROS 2 Python 클라이언트 라이브러리 임포트
from rclpy.node import Node                       # ROS 2 노드 클래스 임포트
from rclpy.action import ActionClient             # ROS 2 Action Client 모듈 임포트
from nav2_msgs.action import ComputePathToPose    # Planner Server 경로 계산용 Action 메시지 임포트
from geometry_msgs.msg import PoseStamped         # 위치/방향 정보 생성을 위한 PoseStamped 메시지 임포트

class PlannerClient(Node):
def __init__(self):
    super().__init__('planner_action_client') # 'planner_action_client' 이름의 노드 초기화
    # Planner Server의 "compute_path_to_pose" 액션 서버와 통신할 ActionClient 생성
    self._action_client = ActionClient(self, ComputePathToPose, 'compute_path_to_pose')

def send_goal(self, goal_x=2.0, goal_y=1.5):
    # 1. Planner Server에 요청할 목표 메시지(Goal) 객체 생성
    goal_msg = ComputePathToPose.Goal()

    # 2. 목표 위치(PoseStamped) 객체 생성 및 좌표계/좌표 설정
    goal_msg.goal = PoseStamped()
    goal_msg.goal.header.frame_id = 'map'     # 글로벌 지도 좌표계 "map" 기준
    goal_msg.goal.header.stamp = self.get_clock().now().to_msg() # 현재 타임스탬프 저장
    goal_msg.goal.pose.position.x = goal_x    # 목표 X 좌표 (m)
    goal_msg.goal.pose.position.y = goal_y    # 목표 Y 좌표 (m)

    # 3. 액션 서버 준비 상태 확인 및 대기
    self._action_client.wait_for_server()

    # 4. Planner Server에 글로벌 경로 생성 비동기 요청 전송
    return self._action_client.send_goal_async(goal_msg)

def main(args=None):
rclpy.init(args=args)                         # ROS 2 Python 통신 시스템 초기화
planner_node = PlannerClient()                # 경로 연산 요청 노드 인스턴스 생성
planner_node.send_goal(goal_x=2.0, goal_y=1.5) # (2.0, 1.5) 위치로 경로 계산 요청
rclpy.spin(planner_node)                      # 콜백 이벤트 대기 루프 실행

if __name__ == '__main__':
main()
