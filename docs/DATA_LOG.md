# 관제 기록(DB) 설계

작성: 2026-10-13 (ktj) · 상태: **계획** (결정 반영 2026-10-13). 지금 구현하지 않음. 시작할 때 다시 허락을 받는다

순찰 중 일어난 일을 나중에 다시 볼 수 있게 남긴다. 팀에서 낸 안("관제서버 SQLite 일지 + 로봇 rosbag 블랙박스")을 바탕으로, 지금 서버·Bridge 구조에 맞춰 정할 것을 채웠다.
실시간 관제 화면(`docs/CONTROL_SCREEN.md`)은 **바꾸지 않는다**. DB는 옆에서 받아 적기만 한다.

## 원칙

| 원칙 | 이유 |
|---|---|
| 실시간 화면은 지금처럼 서버 메모리에서. DB는 기록과 과거 조회에만 | 기존 화면·시험을 깨지 않음 |
| **DB가 느리거나 실패해도 실시간은 멈추지 않음** | 서버는 프로세스 하나에서 비동기로 돈다. DB 쓰기가 막히면 화면 갱신과 정지 명령까지 같이 멈출 수 있음 |
| 시각은 모두 **서버 수신 시각(UTC)** | 텔레메트리 계약의 "로봇·서버 시계를 비교하지 않는다" 원칙 그대로. 로봇 rosbag과 맞춰 볼 때는 `bridge_session_id`를 함께 씀 |
| 원본은 로봇에, 서버에는 요약과 파일 경로만 | 텔레메트리는 8 KiB 제한. 영상·점군은 서버로 보내지 않음 |
| 사람 관련 기록(위치·사진)은 보관 기간을 정하고, 인증 없이는 과거 조회를 열지 않음 | 개인정보. 지금 서버는 인증이 없어서 주소만 알면 누구나 볼 수 있음 |

## 무엇을 어디에 저장하나

| 표 | 저장 위치 | 내용 | 저장 시점 | 단계 |
|---|---|---|---|---|
| `track` | 서버 SQLite | 위치·속도·순찰 상태 (숫자만) | **5초마다 + 순찰 상태가 바뀔 때 바로** | 1 |
| `alerts` | 서버 SQLite | 알림 문구·중요도 | 생길 때, 그리고 지속 문제가 **끝날 때**(`closed_at`) | 1 |
| `commands` | 서버 SQLite | 정지·재개 명령과 단계별 시각, 최종 판정 | **접수할 때 한 줄 넣고, 끝날 때 갱신** | 1 |
| `detections` | 서버 SQLite | 사람 위치(지도 좌표)·추적 ID | 감지될 때 (같은 사람은 5초에 한 번) | 4 |
| `recordings` | 서버 SQLite (경로만) | 이벤트 사진·블랙박스 파일 위치 | 파일을 만들 때 | 3, 5 |
| 이벤트 사진 | 서버 디스크 (JPEG) | | 사건 때만 | 3 |
| 블랙박스 | **로봇 디스크** (rosbag 스냅샷) | 사건 앞뒤 구간 원본 | 사건 때만 | 5 |

팀 안에서 바꾼 점:
- `track`: 5초 간격만으로는 그 사이의 일시정지·실패가 묻혀서, 상태가 바뀔 때도 바로 남김
- `alerts`: 시작만 남기면 언제 끝났는지 몰라서 `closed_at`을 둠 (서버 알림에 이미 `key`·지속 중 여부가 있음)
- `commands`: 끝날 때만 남기면 처리 중 서버가 꺼졌을 때 기록이 없어서, 접수할 때 먼저 넣음. 끝나지 않은 채 남은 줄은 "서버 재시작으로 중단"으로 봄

## 표 구조 (1단계)

모든 표에 `at`(서버 UTC, ISO 문자열)과 `bridge_session_id`가 있다.

### `track`

| 열 | 내용 |
|---|---|
| `at`, `bridge_session_id` | |
| `reason` | `periodic`(5초) / `patrol_changed` |
| `bridge_status` | `connected` / `delayed` / `disconnected` |
| `patrol_state`, `waypoint_index`, `waypoint_name` | 순찰 상태 (없으면 NULL) |
| `x`, `y`, `yaw`, `position_std_m`, `pose_stale` | 위치 (TF 기준, CHANGELOG (26)) |
| `linear_mps`, `angular_radps` | 속도 |

크기: 5초마다 하루 약 17,000줄, 줄당 약 150 B → **하루 약 3 MB**.

### `alerts`

| 열 | 내용 |
|---|---|
| `id` | 서버 알림 ID (UUID) |
| `key`, `kind`, `severity`, `message` | 서버 알림 그대로 |
| `at` | 생긴 시각 |
| `closed_at` | 지속 문제(`active`)가 끝난 시각. 일회성 알림은 NULL |

### `commands`

| 열 | 내용 |
|---|---|
| `request_id` | 서버 명령 ID (기본 키) |
| `command` | `pause` / `resume` |
| `issued_at`, `delivered_at`, `accepted_at`, `finished_at` | 단계별 시각 |
| `stage` | 마지막 단계 (`confirmed`, `rejected`, … `CONTROL_API_DRAFT.md` §3.1). 서버가 재시작됐는데 끝나지 않았으면 `interrupted` |
| `message` | 로봇 응답 문구 (`already paused` 등) |

### `meta`

`schema_version` 한 줄. 표를 바꿀 때 올리고, 서버 시작 시 맞지 않으면 바꾸는 코드를 돌린다.

## 서버에 붙이는 방법

```
[Store (메모리, 지금 그대로)] ──put(표, 줄)──► [큐] ──► [기록 스레드] ──► SQLite (WAL)
      accept · add/close · issue/finish                     실패하면 로그만 남기고 버림
```

| 항목 | 내용 |
|---|---|
| 붙이는 곳 | `server/state.py`의 `accept`(track), `add`·`close`(alerts), `issue`·`take_command`·`apply_result`·`finish`(commands) |
| 새 파일 | `server/db.py`: 연결, 표 만들기, 기록 스레드, 조회 함수 |
| 설정 | `config.json`에 `db_path` (기본 `dashboard/data/limbo.sqlite3`, git에서 제외), `track_interval_s: 5`. 비우면 기록 끔 |
| 큐가 가득 차면 | 가장 오래된 것부터 버리고 경고 로그. 실시간 쪽은 기다리지 않음 |
| 시험 | 기존 시험은 기록을 끈 채로 그대로 통과해야 함. 새 시험은 임시 DB로: 줄 수, 상태 변화 즉시 기록, 명령 접수 → 갱신, 서버 재시작 후 `interrupted`, DB 쓰기 실패해도 텔레메트리 처리 계속 |

## 인증 (0단계)

외부에 공개하는 서비스로 가정한다. 지금은 주소만 알면 누구나 일시정지를 누르고, 누구나 Bridge인 척 텔레메트리를 보낼 수 있다.

| 대상 | 방법 |
|---|---|
| 사람 (화면) | **계정**: 아이디 + 비밀번호로 로그인 → 세션 쿠키 (`HttpOnly`, `Secure`, `SameSite=Strict`). 화면·WebSocket·API 모두 로그인 필요 |
| 로봇 (Bridge) | 사람 계정과 따로, **로봇 토큰**(긴 무작위 문자열)을 `Authorization: Bearer` 헤더로. 토큰은 로봇의 설정 파일·환경 변수에, 서버에는 해시만 |
| 통신 | **HTTPS 필수**. 서버 앞에 리버스 프록시(Caddy 또는 nginx)를 두고 인증서를 붙인다. 서버 자체는 계속 127.0.0.1에서만 받음 |

| 항목 | 내용 |
|---|---|
| 역할 | **관리자**: 보기 + 일시정지·재개 + 계정 관리 / **관찰자**: 보기만 (과거 조회 포함) |
| 계정 만들기 | 가입 화면 없음. 서버에서 명령으로 만든다 (`python -m server.users add 아이디 --role admin`) |
| 비밀번호 저장 | `users` 표에 scrypt 해시 (파이썬 기본 `hashlib.scrypt`, 새 의존성 없음) |
| 로그인 막기 | 같은 아이디로 5번 틀리면 5분 잠금 |
| 세션 | `sessions` 표. 12시간 지나면 다시 로그인. 로그아웃하면 바로 지움 |
| 기록 | `commands`에 누른 계정(`user_id`), 로그인 성공·실패를 `alerts`(kind `auth`)에 |
| `/demo` | 로그인 없이 그대로 (서버를 부르지 않음) |

시험: 로그인 없으면 401(화면은 로그인 화면으로), 관찰자가 명령 → 403, 토큰 없는 Bridge → 401, 잠금, 세션 만료, 로그아웃 후 WebSocket 끊김.

## 과거 조회 API (로그인한 계정만)

| 요청 | 응답 |
|---|---|
| `GET /api/v1/history/track?from=&to=` | 기간 안 `track` (최대 N줄, 넘으면 간격을 늘려 줄임) |
| `GET /api/v1/history/alerts?from=&to=` | 기간 안 알림 |
| `GET /api/v1/history/commands?from=&to=` | 기간 안 명령 |
| `GET /api/v1/history/congestion?from=&to=&cell_m=1` | 격자별 혼잡도 (4단계) |

화면: 지도 카드의 좌표 변환(`ui/src/map.ts`)을 그대로 써서 "지난 경로 다시 보기"와 "혼잡도 지도"를 그린다. 약도로 바꿔도 같이 따라감.

## 혼잡도 (4단계)

정의: **사람이 몰린 정도** (결정함). `detections` + `track`을 쓴다.

### 계산

로봇은 자기가 지나간 곳만 본다. 감지 수를 그대로 세면 **순찰 경로를 자주 지나는 칸이 붐비는 것처럼** 나온다. 그래서 관찰한 시간으로 나눈다.

```
혼잡도(칸) = 그 칸에서 본 서로 다른 사람 수 ÷ 그 칸을 관찰한 시간(분)
```

- 관찰 시간: `track`의 로봇 위치·방향으로 카메라 시야(앞쪽 약 4 m, 시야각)에 그 칸이 들어간 시간을 더한다. 처음에는 "로봇 반경 4 m 안"으로 단순하게 시작해도 됨
- 격자: 1 m (지도 해상도 0.05 m보다 훨씬 굵게)

### 사람 위치는 어디서

사람 인식 노드(`limbo_perception/person_detector.py`)는 이미 `/person_detector/predictions`(`PersonPredictionArray`)로 **사람마다 추적 ID와 위치**를 낸다. 단, 좌표가 **`odom` 기준**이다.
→ Bridge가 받아서 TF로 `map` 기준으로 바꾸고, 텔레메트리 v3에 "최근 감지 목록(ID·x·y, 최대 20명)"으로 싣는다. 같은 ID는 서버에서 5초에 한 번만 저장한다.

## 이벤트 사진 (3단계)

- 언제: 정지 명령, 오류 알림, (나중에) 사람 접근 등 정해진 사건 때만
- 통로: 카메라(관제 화면 C)와 같은 영상 통로에서 한 장을 받아 `POST /api/v1/recordings/photo`로 저장. **카메라를 먼저 만들고 그 위에 얹는다**
- 저장: `dashboard/data/photos/날짜/ID.jpg`, `recordings`에 경로·사건 종류·관련 알림·명령 ID

## 블랙박스 (5단계)

**rosbag 스냅샷**으로 한다. 저장소는 **Jetson에 연결한 1 TB**.

- `ros2 bag record --snapshot-mode`(Jazzy)로 최근 N초를 메모리 버퍼(`--max-cache-size`)에 계속 들고 있다가, 스냅샷 서비스가 불리면 그 버퍼를 파일로 쓴다
- 사건 때만 파일이 생기므로 원본 토픽(LiDAR·카메라)을 넣어도 1 TB로 오래 간다. 대신 **버퍼 크기가 Jetson 메모리를 먹는다** (아래 크기로 앞 N초 × 초당 크기)
- 사건 "뒤" 구간도 필요하면 사건 직후가 아니라 N초 뒤에 스냅샷을 부른다 (앞뒤를 한 번에 담음)

토픽별 대략 크기 (시뮬레이션 기준, 실제 로봇에서 다시 잼). 버퍼 크기를 정할 때 씀:

| 토픽 | 시간당 |
|---|---|
| odom·TF·순찰 상태·명령 등 숫자 | 1 GB 미만 |
| 카메라 압축(JPEG, 640×360, 5 Hz) | 약 0.5 GB |
| LiDAR 점군 원본 (MID-360, 10 Hz) | 약 10~20 GB |
| 카메라 원본·depth (15 Hz) | 100 GB 이상 |

- 예: 앞뒤 30초씩(60초), 숫자 + 압축 카메라 + LiDAR면 버퍼 약 0.3 GB. 카메라 원본까지 넣으면 약 2 GB → Jetson 메모리를 보고 정함
- 트리거: 명령 실패·확인 불가, 오류 알림, 순찰 실패. 서버가 명령 통로로 Bridge에 알리면 Bridge가 스냅샷 서비스를 부른다
- 파일은 **Jetson 1 TB**에 있어서 서버가 직접 열 수 없다. `recordings`에 `location: robot`, 경로, 크기, 사건 종류를 남긴다. 꺼내 볼 때는 로봇에서 직접 복사
